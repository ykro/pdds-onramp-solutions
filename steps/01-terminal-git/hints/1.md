# Pista 1. Empieza por inspeccionar el log y planear el flujo

Antes de escribir código o abrir ramas, revisa las primeras líneas de `data/access.log` directamente desde la terminal con `head` y `wc -l`. Un buen script de shell procesa texto estructurado combinando utilidades pequeñas como `wc`, `awk`, `sort`, `uniq` y `head` mediante pipes.

Respecto a Git, piensa en cada commit como una unidad lógica que otra persona puede revisar y revertir por separado. Redacta la historia de usuario en `docs/stories/001-order-history.md` antes de abrir el Pull Request que cierra tu issue.

Si necesitas refrescar cómo moverte por carpetas o encadenar comandos, revisa [example/intro-terminal.md](../example/intro-terminal.md). Cuando quieras bajar al detalle del script, abre [la pista 2](2.md).
