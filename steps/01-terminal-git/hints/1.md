# Pista 1. Inspecciona el log y el script antes de editar

Antes de abrir una rama o tocar código, revisa las primeras líneas de `data/access.log` con `head` y `wc -l`, y lee `scripts/log_report.sh` de arriba a abajo. Un script de shell claro procesa texto por columnas encadenando utilidades pequeñas como `wc`, `awk`, `sort`, `uniq` y `head`.

En Git, cada rama nueva aísla un cambio completo para que otra persona pueda revisarlo en un Pull Request antes de integrarlo a `main`. Redacta tu historia de usuario en `docs/stories/001-order-history.md` y contrástala con [examples/code-review.md](../../../examples/code-review.md).

Si quieres refrescar rutas, permisos y pipes en la terminal, abre [example/intro-terminal.md](../example/intro-terminal.md). Para bajar al detalle de los dos bugs en el script, pasa a [la pista 2](2.md).
