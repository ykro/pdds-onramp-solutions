# Pista 2. Los dos bugs en `scripts/log_report.sh` y la historia de usuario

Para cumplir `CA-1.1`, revisa cómo valida `scripts/log_report.sh` el archivo recibido como primer argumento. Antes de leer el log, comprueba `[[ $# -lt 1 ]] || [[ ! -f "$1" ]]`, imprime el error en `stderr` y termina con `exit 1`. También verifica que el archivo tenga permiso de ejecución con `chmod +x scripts/log_report.sh`.

Para cumplir `CA-1.2`, inspecciona las columnas de `data/access.log`. La columna `$3` contiene la ruta del endpoint y la columna `$4` contiene el código HTTP. El script original cuenta errores `4xx`, así que cambia el patrón de `awk` para filtrar `^5[0-9][0-9]$` en `errors_5xx`, conservando `total_requests` y `top_endpoints`.

Para cumplir `CA-1.3`, completa `docs/stories/001-order-history.md` con las palabras `Como`, `Quiero` y `Para`, además de al menos dos escenarios con `Dado`, `Cuando` y `Entonces`. Luego abre tu Pull Request siguiendo [examples/code-review.md](../../../examples/code-review.md).

Si necesitas los comandos exactos para probar cada parte, abre [la pista 3](3.md).
