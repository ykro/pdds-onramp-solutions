# Pista 2. Estructura de `scripts/log_report.sh` y formato de salida

Arranca `scripts/log_report.sh` con `#!/usr/bin/env bash` y `set -euo pipefail`. Antes de leer nada, comprueba que recibiste un argumento y que el archivo existe con `[[ $# -lt 1 ]] || [[ ! -f "$1" ]]`, imprimiendo un mensaje a `stderr` y saliendo con `exit 1` para cumplir `CA-1.1`.

Para cumplir `CA-1.2`, cada línea de `data/access.log` tiene columnas separadas por espacios donde la columna `$3` es el endpoint y la columna `$4` es el código HTTP. Usa `wc -l` para `total_requests`, `awk` filtrando `^5[0-9][0-9]$` para `errors_5xx`, y `awk '{ print $3 }' | sort | uniq -c | sort -nr | head -n 3` para los tres endpoints más frecuentes en `top_endpoints`.

En `docs/stories/001-order-history.md`, incluye las palabras clave `Como`, `Quiero`, `Para` y al menos dos escenarios con `Dado`, `Cuando` y `Entonces` (`CA-1.3`), contrastando tu texto y tu PR con `examples/historia-y-pr.md`.
