# Pista 2. Los dos bugs en `scripts/log_report.sh` y la historia de usuario

Para cumplir `CA-1.1`, revisa cómo valida `scripts/log_report.sh` el archivo recibido como primer argumento. Antes de leer el log, el script debe detenerse si no recibe argumento o si el archivo no existe, escribir el error en `stderr` y salir con un código distinto de cero. También verifica que el archivo tenga permiso de ejecución con `chmod +x scripts/log_report.sh`.

Para cumplir `CA-1.2`, inspecciona las columnas de `data/access.log`. La columna `$3` contiene la ruta del endpoint y la columna `$4` contiene el código HTTP. El script original cuenta errores `4xx`. Revisa el patrón de `awk` de `errors_5xx` y decide qué debe cambiar para contar solo los códigos que empiezan con 5, sin tocar `total_requests` ni `top_endpoints`.

Para cumplir `CA-1.3`, completa `docs/stories/001-order-history.md` con las palabras `Como`, `Quiero` y `Para`, además de al menos dos escenarios con `Dado`, `Cuando` y `Entonces`. Luego abre tu Pull Request siguiendo [examples/code-review.md](../../../examples/code-review.md).

Si necesitas los comandos exactos para probar cada parte, abre [la pista 3](3.md).
