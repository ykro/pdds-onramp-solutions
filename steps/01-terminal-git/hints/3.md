# Pista 3. Cómo encontrar los dos bugs por tu cuenta

Antes de editar, mira qué códigos de estado trae el log y cuántos hay de cada uno.

```bash
head -n 5 data/access.log
awk '{ print $4 }' data/access.log | sort | uniq -c
```

Compara ese conteo con lo que imprime hoy `./scripts/log_report.sh data/access.log`. Si `errors_5xx` coincide con los `4xx`, el patrón del `awk` está mirando el primer dígito equivocado. Un patrón que solo acepta tres dígitos que empiezan con 5 tiene esta forma.

```bash
awk '$4 ~ /^?[0-9][0-9]$/ { c++ } END { print c + 0 }' data/access.log
```

Para el código de salida, prueba el script con un archivo que no existe y revisa `echo "exit=$?"`. La validación del inicio necesita esta estructura, y te toca decidir qué número devuelve.

```bash
if [[ ! -f "$INPUT_FILE" ]]; then
  echo "Error: ..." >&2
  exit ?
fi
```

Trabaja en una rama (`git checkout -b fix/step-1-log-report`), dale permiso de ejecución con `chmod +x` y completa la historia de usuario. Antes de abrir el PR, revisa tu diff con [examples/code-review.md](../../../examples/code-review.md) y corre `make check STEP=1`.
