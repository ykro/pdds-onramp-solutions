# Pista 3. Cómo encontrar los dos bugs por tu cuenta

Compara el conteo de la pista 1 con lo que imprime hoy `./scripts/log_report.sh data/access.log`. Si `errors_5xx` coincide con los `4xx`, el patrón del `awk` está mirando el primer dígito equivocado. Un patrón que solo acepta tres dígitos que empiezan con 5 tiene esta forma.

```bash
awk '$4 ~ /^?[0-9][0-9]$/ { c++ } END { print c + 0 }' data/access.log
```

Para el archivo que falta, prueba el script sin argumento y con un archivo que no existe, y revisa `echo "exit=$?"`. Hoy `set -e` ya corta el script, pero con un mensaje de bash difícil de leer. La validación va antes de usar `$LOG_FILE` y necesita esta estructura; el texto exacto del error está en `CA-1.1`.

```bash
if [[ $# -lt 1 ]] || [[ ! -f "$1" ]]; then
  echo "Error: ..." >&2
  exit ?
fi
```

Trabaja en una rama (`git switch -c fix/step-1-log-report`) y completa la historia de usuario. Antes de abrir el PR, revisa tu diff con [examples/code-review.md](../../../examples/code-review.md) y corre `make check STEP=1`.
