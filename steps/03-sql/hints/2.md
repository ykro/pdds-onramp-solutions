# Pista 2. Bloqueo pesimista, code review e índices

En PostgreSQL, el nivel de aislamiento por defecto (`READ COMMITTED`) permite que dos transacciones concurrentes lean la misma fila de `products` antes de que alguna haga `UPDATE`. Para serializar el acceso sobre un producto en `orders_repo.place_order()` (`CA-3.3`), bloquea la fila al leerla con `SELECT id, price_cents, stock FROM products WHERE sku = %s FOR UPDATE`.

En el code review del PR `review/step-3-orders-by-sku` (`CA-3.4`), inspecciona `steps/03-sql/buggy_snapshot.py` para detectar dos defectos concretos, concatenación de strings que abre una inyección SQL y ausencia del filtro `o.status <> 'cancelled'`. Corrige `orders_repo.find_orders_by_sku()` con parámetros `%s` y escribe pruebas en `backend/tests/step3/test_student_review.py` que fallen con `AssertionError` contra `buggy_snapshot.py`.

Para `CA-3.6`, crea `idx_order_items_product_id` en `db/migrations/003_indexes.sql` y confirma el plan con `EXPLAIN (ANALYZE, BUFFERS)`.

Si necesitas ver el patrón SQL exacto, abre [la pista 3](3.md).
