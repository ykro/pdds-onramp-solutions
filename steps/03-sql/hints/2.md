# Pista 2. Bloqueo pesimista, orden de bloqueo e índices

En PostgreSQL, el nivel de aislamiento por defecto (`READ COMMITTED`) permite que dos transacciones concurrentes lean la misma fila de `products` antes de que alguna haga `UPDATE`. Para serializar el acceso sobre un producto específico, bloquea las filas al leerlas con `SELECT id, price_cents, stock FROM products WHERE id = ANY(%s) ORDER BY id FOR UPDATE`.

Fíjate en el `ORDER BY id` antes de `FOR UPDATE`. Si una transacción bloquea el producto 1 y luego el 2, mientras otra bloquea el 2 y luego el 1, provocarás un deadlock. Ordenar los IDs de forma determinista elimina ese riesgo.

Para `CA-3.6`, revisa las columnas presentes en `WHERE` y `ORDER BY` de tus consultas más frecuentes y confirma con `EXPLAIN (ANALYZE, BUFFERS)` que PostgreSQL elige un `Index Scan`.

Si necesitas ver el patrón SQL exacto, abre [la pista 3](3.md).
