# Pista 3. Patrones SQL exactos para reportes y consultas seguras

En `db/queries/monthly_sales.sql` (`CA-3.1`), devuelve las columnas `month`, `order_count` y `revenue_cents`.

```sql
SELECT
    TO_CHAR(created_at AT TIME ZONE 'UTC', 'YYYY-MM') AS month,
    COUNT(*) AS order_count,
    SUM(total_cents) AS revenue_cents
FROM orders
WHERE status <> 'cancelled'
GROUP BY 1
ORDER BY 1;
```

En `db/queries/top_products.sql` (`CA-3.2`), devuelve `sku`, `name` y `units_sold` con `LIMIT 5`.

```sql
SELECT
    p.sku,
    p.name,
    SUM(oi.quantity) AS units_sold
FROM order_items oi
JOIN products p ON p.id = oi.product_id
JOIN orders o ON o.id = oi.order_id
WHERE o.status <> 'cancelled'
GROUP BY p.id, p.sku, p.name
ORDER BY units_sold DESC, p.sku ASC
LIMIT 5;
```

En `find_orders_by_sku()` dentro de `backend/tiendita/repositories/orders_repo.py` (`CA-3.3`), pasa `(sku,)` como segundo argumento de `cur.execute` y filtra `AND o.status <> 'cancelled'`. Así el payload `' OR '1'='1` busca un SKU literal inexistente y devuelve una lista vacía.

Levanta la base con `make db-up` y valida los tres criterios con `make check STEP=3`.
