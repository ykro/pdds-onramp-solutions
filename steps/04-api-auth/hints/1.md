# Pista 1. Separa transporte HTTP, lógica de negocio y persistencia

Cuando una ruta de FastAPI abre cursores SQL y decide descuentos dentro de la misma función, probar una regla exige levantar una base de datos completa. Divide el backend en tres capas con responsabilidades claras.

- Las rutas traducen HTTP, validan cuerpos con Pydantic y llaman a un servicio.
- Los servicios aplican reglas de negocio y coordinan repositorios sin conocer SQL ni códigos HTTP.
- Los repositorios leen y escriben en PostgreSQL (o en un diccionario en memoria durante las pruebas unitarias).

Revisa un ejemplo completo de esta separación con `Depends` en [example/layered_endpoint_example.py](../example/layered_endpoint_example.py). Cuando estés listo para ver autenticación e idempotencia, abre [la pista 2](2.md).
