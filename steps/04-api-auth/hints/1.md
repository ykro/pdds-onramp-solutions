# Pista 1. Separa transporte HTTP, lógica de negocio y persistencia

Cuando una ruta de FastAPI abre cursores SQL y decide reglas de negocio dentro de la misma función, probar un cambio exige levantar una base de datos completa. Este backend divide el flujo en tres capas claras.

- Las rutas en `backend/tiendita/api/app.py` traducen HTTP, validan entradas y delegan en el servicio.
- El servicio en `backend/tiendita/services/store_service.py` aplica reglas de negocio y autorización sin conocer SQL ni códigos HTTP.
- El repositorio en `backend/tiendita/repositories/orders_repo.py` lee y escribe en PostgreSQL, y en pruebas puede sustituirse por un repositorio en memoria.

Revisa el patrón completo con `Depends` en [example/layered_endpoint_example.py](../example/layered_endpoint_example.py). Cuando quieras ver la fuga de autorización y el endpoint nuevo, abre [la pista 2](2.md).
