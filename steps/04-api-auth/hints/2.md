# Pista 2. Autorización por usuario y el nuevo endpoint `GET /api/products/{sku}`

La verificación de JWT contra el servidor JWKS ya viene implementada en `backend/tiendita/api/auth.py`, donde `get_current_user_id` rechaza con `401` tokens faltantes, expirados o mal firmados y entrega el `sub` del usuario.

Para corregir `CA-4.1`, inspecciona `StoreService.get_my_orders(user_id)` en `backend/tiendita/services/store_service.py`. Incluso si el repositorio devuelve pedidos de varios usuarios, el servicio debe garantizar la regla de autorización filtrando únicamente las órdenes cuyo `user_id` coincida con el usuario autenticado.

Para cumplir `CA-4.2` y `CA-4.3`, agrega `GET /api/products/{sku}` atravesando las tres capas. Expone `get_product_by_sku(sku)` en `orders_repo.py`, llámalo desde `StoreService.get_product(sku)` lanzando `KeyError` cuando devuelva `None`, y traduce `KeyError` a `HTTPException(status_code=404)` dentro de `app.py`. FastAPI registrará la ruta en `/api/openapi.json` en automático.

Si buscas el esqueleto exacto por capa, abre [la pista 3](3.md).
