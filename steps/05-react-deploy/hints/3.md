# Pista 3. Lista de verificación antes de correr `make check` y `make check-prod`

Ejecuta estos comandos dentro de `frontend/` para detectar errores de tipos y fallas en las vistas antes de desplegar.

```bash
npm run typecheck
npm test
npm run build
```

Verifica tres puntos frecuentes que suelen fallar en `CA-5.1` a `CA-5.4`.

1. Confirma `"strict": true` en `tsconfig.json` y completa `frontend/src/hooks/useCart.ts` junto con `LoginView`, `CatalogView` y `OrdersView` sin usar `any`.
2. Al desplegar el proyecto unificado en Vercel conectado a Neon y Neon Auth, escribe la URL pública en `deploy.json` bajo la clave `app_url` (por ejemplo `{"app_url": "https://tu-app.vercel.app"}`) y valida en producción con `make check-prod`.
3. Antes de ejecutar `make check-prod`, comprueba desde la terminal que `/api/health` responde `200`, `/api/orders/mine` sin token responde `401` y `/` carga el frontend.

```bash
APP_URL=$(python3 -c "import json; print(json.load(open('deploy.json'))['app_url'].rstrip('/'))")
curl -fsS "$APP_URL/api/health"
curl -s -o /dev/null -w "%{http_code}\n" "$APP_URL/api/orders/mine"
```

Para el alcance extendido (`CA-5.4`), ejecuta `make check STEP=5 EXTRA=1` para correr `frontend/e2e/checkout.spec.ts` con Playwright y `axe-core`, y corre `npm --prefix frontend audit` como revisión informativa.
