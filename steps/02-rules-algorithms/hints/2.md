# Pista 2. Orden de cálculo y pruebas que detectan bugs plantados

Define un orden explícito y único en tu cálculo de checkout. Primero valida el catálogo y el stock de cada línea, luego suma el subtotal en centavos, aplica el cupón sin dejar que el resultado baje de `0`, y calcula el impuesto sobre la base ya descontada usando redondeo entero consistente.

Para superar `CA-2.5` (las versiones con bugs plantados), pregúntate qué pasaría si alguien cambia un `>=` por `>`, olvida limitar el descuento al subtotal o calcula el impuesto antes del descuento. Cada uno de esos errores debe hacer fallar al menos un test específico en tu suite.

Para el criterio extendido `CA-2.6`, ordena los productos por precio una sola vez al construir el índice y usa el módulo estándar `bisect` para localizar rangos en tiempo logarítmico.

Si buscas la forma concreta de escribir los cálculos y pruebas, abre [la pista 3](3.md).
